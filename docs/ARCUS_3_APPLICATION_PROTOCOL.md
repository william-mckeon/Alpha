# Arcus 3 Phase 3 application protocol

Scope: read-only application integration around the unchanged pinned dense donor.
The application uses a LangChain BaseChatModel adapter and a LangGraph model/tool
loop. The Phase 2 Runnable path, frozen fixtures and scores remain separate.
No training, expert expansion, cloud job, publication or Alpha resume occurs here.

## Local use

Run the five bounded integration probes:

```powershell
& scripts/start_arcus3.ps1 -Mode application -Root runs/arcus3/application-unique-id -StopAt ([DateTimeOffset]::Now.AddMinutes(20))
```

For custom questions, provide a UTF-8 JSON file containing 1–8 requests:

```json
[
  {"session":"demo","prompt":"My favorite color is violet.","tools":false},
  {"session":"demo","prompt":"What is my favorite color?","tools":false},
  {"session":"math","prompt":"Use calculate to add 17 and 25, then explain the result.","tools":true}
]
```

Pass its local path with `-RequestsFile`. It is mounted read-only, and only the
declared fields are accepted. Each prompt is limited to 4,000 characters. The
launcher uses a fresh run directory and an explicit deadline of at most 30 minutes.
This is a bounded request-file interface, not a continuously running web service.

## Message contract and tools

The adapter retains the original donor chat template and records every serialized
prompt and generated token ID in the report. Natural conversation uses the Arcus
identity instruction. Binding tools adds exact definitions and a JSON-call protocol.
Call IDs are generated by the adapter and retained in subsequent assistant and
tool messages. Malformed tool JSON produces an explicit invalid-call status.
One complete leading JSON call followed by prose is accepted with a protocol
warning. The prose is preserved but never treated as a tool result; the real tool
still executes and its observation is returned to the model. Ambiguous multiple
leading calls and names not bound for the request are rejected. A non-tool answer
that hits its token cap receives response_truncated status and is not memorized.

Only exact schemas for `echo` and `calculate` may be bound. Echo returns actual
input text; calculate performs validated add/subtract/multiply/divide arithmetic.
Inputs must be finite numbers of magnitude at most one million; booleans are not
numbers. Unknown tools, extra arguments, invalid types and division by zero return
structured errors. Results are fed back to the model, which generates its answer.
Neither tool accesses the network, host files, shell or arbitrary Python. They
are real deterministic local functions, distinct from Phase 2's canned fixtures.
The previous restricted Python evaluator remains available in baseline mode.

The graph permits at most three model calls and two tool calls per turn. It stops
explicitly on invalid JSON or exhausted budgets. It checks pause/deadline before
each model/tool node; generation checks them after each decoded token, and the
launcher can terminate only its own container at deadline. Cancellation and tool
error observations are covered with controlled fixtures, not counted as model skills.

## Memory and storage

Default conversation memory is ephemeral, separated by validated session IDs.
History keeps at most four complete turns and 12,000 serialized characters. Oversize
old turns are removed whole; unfinished tool-call sequences are not retained.
Generation additionally rejects inputs exceeding 2,048 tokens; it never silently
clips a tool-result sequence. A new session resets conversational context.

`-PersistMemory` explicitly writes session JSON under the run's `sessions/` folder.
The ConversationMemory API supports loading that directory and deleting individual
sessions. The launcher does not automatically reopen an old run or clear its pause.
Persistence is not learning, and stored chat does not modify model weights. Raw
reports themselves contain prompts and responses even when session persistence is
disabled; this flag controls reusable history, not diagnostic-report retention.

## Resources and evidence

One controlled Docker CUDA job, shared GPU lock, 8 GiB Docker memory, CPU 2, PID 128,
70% CUDA allocator. The user-disabled free-memory watchdog stays disabled. Original
donor files mount read-only. No Docker socket is exposed to the model container.

`application-report.json` contains requests, full LangChain messages, tool IDs,
observations, responses, status, token usage, truncation and resources.
`application-transcripts.json` is checkpointed after each request. Container logs,
runtime identity and exit state accompany the report. These application probes do
not replace the frozen baseline or establish broad tool reliability.
