Stage 0 — Babble (now, free on the 5080). Pretrain the 0.5B to fluency — coherent generation, not gibberish. The substrate is 100% built; you just run it. This is the prerequisite for everything: SFT can't teach language to a base that can't talk (specs/0006:44).

Stage 1 — Build + validate the growth operator (the calibration rung). Build the net2net/expert-duplication operator. Grow 0.5B→1B, continue-train, and compare grown-1B val_ppl against a from-scratch 1B. This is the one rung where from-scratch is affordable as a reference — it's where you prove the operator preserves quality before you ever have to trust it at 32B where you can't check.

Stage 2 — Learn to talk in the agent's format. Define the o200k chat template + tool tokens (piece 2), build the masked-SFT path (piece 3), render openagent-code's trajectories (trajectory.py → convert.py rows) into masked SFT. The teacher (gpt-oss-120b) supplies the examples to imitate.

Stage 3 — Close the loop, read-only. Build the serving shim (piece 4), plug Arcus behind CODE_API_BASE, run compare.py with Arcus as student vs a base. Now the flywheel can see Arcus. Nothing self-improves yet — you're proving the plumbing turns.

Stage 4 — Learn from doing (the experiential SFT flywheel). Turn it: Arcus serves → runs tasks → capture → curate (is_trainable is your anti-collapse filter — you only train on what verified, convert.py:92) → masked-SFT → eval-gate → promote. Keep old + new data each round — that rehearsal is your consolidation mechanism against catastrophic forgetting. SFT-only; this is where "new data every round" becomes real.

Stage 5 — Earn judgment (RLVR, the confidence loop). Only after SFT plateaus (both repos insist on this order). Repurpose verify into a reward (piece 5), reward confident-and-right / penalize confident-and-wrong. This is where calibration — knowing what it doesn't know — actually gets learned, because RL can distinguish the two failure modes SFT can't.

Stage 6 — Grow up the ladder. Repeat grow→train→SFT→RL at 1→2→4→8→…→85B. Two hard requirements come due here: build FSDP (the top presets have no distributed code), and grow the dataset alongside each rung (Chinchilla — retrieval offloads facts, never the reasoning-token budget). Re-validate the growth operator at each low rung; trust it up high.
